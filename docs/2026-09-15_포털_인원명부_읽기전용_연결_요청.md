# 직영인사 포털 → 큐브티 인원명부 읽기 전용 연결 요청

2026-09-15 · 요청: 큐브티(큐브) · 결정: 디렉터님 · **수정본 v3(권한 회수 · 다시 실행해도 안전)**

## 한 줄 요약

큐브티가 포털 인원명부를 **하루 한 번 읽기만** 합니다. 포털 코드는 고치지 않습니다.
포털 담당자께는 Supabase SQL 편집기에서 아래 SQL 을 한 번 실행하고, 토큰 하나를 만들어 디렉터님께 전달해 주시는 것만 부탁드립니다.

## 1. 뷰와 읽기 전용 역할 만들기 (SQL 편집기에서 한 번)

인원명부 화면과 같은 기준(본사 제외)으로, 큐브티가 쓰는 칸만 담습니다.
주민번호·계좌·주소·평가·상담 등은 뷰에 **넣지 않습니다**.

```sql
-- 큐브티가 읽을 칸만 담은 뷰 (직영 인원만 — 인원명부 화면의 isJikyoung 과 같은 기준)
create or replace view public.cubetee_roster as
select e.ems_id, e.name, e.status, e.job, e.position, e.branch,
       e.join_date, e.leave_date, e.email_company, e.updated_at
from public.hr_employees e
where coalesce(e.branch, '') !~ '^본사'
  and coalesce(e.status, '') <> '본사발령';

-- ⚠ 반드시: Supabase 는 public 스키마의 새 뷰에 anon·authenticated 권한을 기본으로 준다.
--   이 뷰는 만든 사람 권한으로 돌아 원본 표의 RLS 를 건너뛰므로, 회수하지 않으면
--   포털 웹에 공개된 anon 키만으로 누구나 인원명부를 읽을 수 있다.
revoke all on public.cubetee_roster from anon, authenticated, public;

-- 읽기 전용 역할 — 이 뷰 하나만 SELECT 할 수 있다(원본 표 hr_employees 는 못 본다)
-- 이미 있으면 넘어간다 — 파일을 통째로 다시 돌려도 앞의 revoke 가 되돌려지지 않게(SQL 편집기는 한 번에 한 트랜잭션)
do $$ begin
  create role cubetee_reader nologin noinherit;
exception when duplicate_object then null;
end $$;
grant usage on schema public to cubetee_reader;
grant select on public.cubetee_roster to cubetee_reader;
grant cubetee_reader to authenticator;
-- 아래 확인 2 에서 `set role cubetee_reader` 가 되도록(없으면 권한 오류가 난다)
grant cubetee_reader to postgres;
```

### 확인 (셋 다 맞아야 합니다)

1. `set role anon; select count(*) from public.cubetee_roster;` → **permission denied** (가장 중요). `set role authenticated;` 로도 같은 결과.
2. `set role cubetee_reader; select count(*) from public.cubetee_roster;` → 숫자, `select count(*) from public.hr_employees;` → permission denied.
3. 끝나면 `reset role;`

## 2. 읽기 전용 토큰 만들기

Supabase 대시보드 → Project Settings → API → **JWT Secret(레거시)** 을 환경변수로 두고 PC 에서 한 번 실행합니다.
만료는 1년입니다(만료 한 달 전에 같은 방법으로 다시 만들면 됩니다).

```bash
JWT_SECRET='(JWT Secret)' node -e "const c=require('crypto');const b=o=>Buffer.from(JSON.stringify(o)).toString('base64url');const n=Math.floor(Date.now()/1000);const h=b({alg:'HS256',typ:'JWT'});const p=b({role:'cubetee_reader',iss:'supabase',iat:n,exp:n+365*86400});console.log(h+'.'+p+'.'+c.createHmac('sha256',process.env.JWT_SECRET).update(h+'.'+p).digest('base64url'))"
```

### 토큰 확인

```bash
# anon 키만 — 거부돼야 한다(401 또는 permission denied)
curl -s "https://<ref>.supabase.co/rest/v1/cubetee_roster?select=ems_id&limit=1" -H "apikey: <anon 키>"
# anon 키 + 토큰 — 한 줄이 나와야 한다
curl -s "https://<ref>.supabase.co/rest/v1/cubetee_roster?select=ems_id&limit=1" -H "apikey: <anon 키>" -H "Authorization: Bearer <토큰>"
```

토큰 요청에서 "JWT invalid"·"JWSError" 가 나오면 프로젝트가 새 JWT 서명 키로 옮겨간 것입니다. 큐브티 세션으로 알려 주시면 방법을 바꿉니다.

## 3. 디렉터님께 전달할 것 (채팅·문서·커밋에 값을 적지 말고 직접 전달)

| 항목 | 값 |
|---|---|
| 주소 | `https://<프로젝트 ref>.supabase.co/rest/v1/cubetee_roster` |
| API 키 | 프로젝트의 anon(또는 publishable) 키 |
| 토큰 | 2번에서 만든 값 |

디렉터님이 큐브티 관리자 → 「포털 인원명부 연동」 → 연결 정보에 넣고 「연결 확인」을 누르면 끝입니다.

## 큐브티가 이 값으로 하는 일

- 매일 06:30 에 뷰를 한 번 읽습니다(요청 1회).
- 사번으로 큐브티 직원과 맞추고, 이름·지점·직책·직급·입사일을 맞춥니다.
- 입사·퇴사·휴직·복직은 큐브티 본부가 확인 버튼을 눌러야 반영됩니다.
- 포털에는 아무것도 쓰지 않습니다. 연결을 끊으려면 `revoke select on public.cubetee_roster from cubetee_reader;` 한 줄이면 됩니다.
