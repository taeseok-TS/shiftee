# 공통 성공 기준 (Success Criteria)

모든 미션은 아래 기준을 **전부** 충족해야 "완료"로 보고할 수 있다.

## 코드 기준

1. **외과적 변경**: 변경된 모든 줄이 미션 브리프의 요구사항으로 직접 추적 가능해야 한다.
   인접 코드 리팩터링, 포매팅 변경, 무관한 개선 금지.
2. **기존 스타일 준수**: 이 코드베이스의 관례를 따른다 —
   - API 응답: `NextResponse.json({ error: "한국어 메시지" }, { status: N })`
   - 인증: `getSession()` (`src/lib/auth.ts`), 권한 거부는 401/403
   - MANAGER 스코프: `session.branch` 기반 필터
   - 감사 로그: `logAudit()` (`src/lib/audit.ts`) — 관리자 데이터 변경에는 반드시 남길 것
   - 주석/메시지/UI 문구는 한국어
3. **Next.js 16 규칙**: 동적 라우트 params는 `Promise<{ id: string }>` 타입, `await params`로 사용.
4. **Prisma**: 스키마 변경은 `prisma db push` 전제 (migrate dev 금지). 스키마를 바꾸면
   워게임 문서의 해당 수(move)에 명시된 데이터 백필(backfill)도 반드시 수행.

## 검증 기준

5. **자체 검증 후 보고**: "될 것이다"가 아니라 실제로 실행해 관찰한 결과로 보고한다.
   각 워게임의 "검증" 섹션에 나열된 시나리오를 전부 수행.
6. **회귀 확인**: 미션이 건드린 데이터를 소비하는 다른 화면/API 최소 2곳을 열어
   깨지지 않았음을 확인 (각 워게임에 소비처 목록 있음).
7. **실패 경로 검증**: 성공 경로만이 아니라, 워게임에 명시된 실패 시나리오 중
   재현 가능한 것 1개 이상을 실제로 재현해 에러 처리가 의도대로임을 확인.

## 보고 기준

8. 완료 보고에는 다음을 포함한다:
   - 실제로 밟은 수(move) 목록과 각 수의 실제 관찰 결과
   - 예상과 달랐던 지점 + 어떤 분기 트리거를 따랐는지
   - 수행하지 못한 검증과 그 이유
9. **중단 조건에 걸리면** 부분 완료 상태로 멈추고, 어디까지 했는지 + 무엇에 막혔는지 보고.
   막힌 채로 우회 구현(스텁, 하드코딩, 조건 완화)을 하지 않는다.
