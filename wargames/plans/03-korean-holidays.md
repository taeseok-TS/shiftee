# 워게임 03 — 한국 공휴일 연동

> 실행자에게: 워게임 규칙은 `wargames/README.md`, 공통 성공 기준은 `wargames/success.md` 참조.

## 0. 정찰 결과 (2026-07 검증 완료)

1. **휴가 일수 계산이 주말만 제외**: `api/leave/route.ts:93` —
   `allDays.filter(d => getDay(d) !== 0 && getDay(d) !== 6).length`.
   공휴일이 낀 연차는 공휴일까지 차감된다. 이것이 미션의 핵심 표적.
2. **지각/조퇴 판정이 달력을 모름**: `api/attendance/[id]/auto-fill/route.ts:47-50` —
   출근 9시 이후 = LATE, 퇴근 18시 이전 = EARLY_LEAVE, 요일/공휴일 무관.
   clock-in/clock-out 라우트에도 유사 판정이 있는지 실행 시 확인 필요.
3. `ScheduleType.HOLIDAY` enum이 존재하고 `api/schedule/route.ts:92`에서 카운트되지만
   **수동 입력**용 — 자동 공휴일 데이터가 아니다. 이것과 새 공휴일 데이터를 혼동하지 말 것.
4. 공휴일 판정이 필요한 소비처 후보: 휴가 일수 계산(확정), 출퇴근 상태 판정(정책 대기),
   일정 캘린더 표시, 대시보드 통계(근무일 수 기반이면).
5. 외부 API 제약: 공공데이터포털 특일정보 API는 서비스 키 필요 (ledger
   `(공공데이터포털_서비스키)` 🔴 미입력). 서버는 개인 PC — 외부 API 장애/오프라인 내성이 필요.

## 1. 설계 결정 (실행 전 확정)

**음력 공휴일(설/추석)과 대체공휴일은 계산하지 말고 데이터로 취급한다.** 음력 변환과
대체공휴일 규정(공휴일별 적용 여부가 다름)은 직접 구현하면 반드시 틀린다.
→ 아키텍처: **DB 테이블이 유일한 진실 소스(single source of truth)**, 채우는 방법만
API/수동으로 분기. 판정 코드는 데이터 출처를 모르게 한다.

```prisma
model Holiday {
  id    String   @id @default(cuid())
  date  DateTime @unique @db.Date
  name  String
}
```

## 2. 수순 (Moves)

### Move 1 — Holiday 모델 + 판정 유틸

스키마에 Holiday 추가 → `db push` (서버 종료 후 — Windows DLL 락, CLAUDE.md).
`lib/holidays.ts`에 기간 조회 헬퍼: `getHolidaySet(start, end): Promise<Set<string>>`
(키는 `YYYY-MM-DD` — `@db.Date` 컬럼과 타임존 안전하게 비교하기 위해 문자열 키 사용).

- **가장 가능성 높은 실패**: 타임존. `@db.Date`는 UTC 자정으로 저장되는데 서버 로컬(KST)
  `Date`와 비교하면 하루 밀린다. **신호**: 3월 1일 공휴일이 2월 28일 또는 3월 2일로 판정.
  **대응 수**: Date 객체 직접 비교 금지 — 저장·비교 모두 `YYYY-MM-DD` 문자열로 정규화.
  기존 코드가 날짜를 어떻게 다루는지(`api/leave/route.ts`의 startDate 처리) 먼저 관찰하고
  같은 방식을 따를 것.

### Move 2 — 데이터 채우기 (분기)

**분기 트리거**: ledger `(공공데이터포털_서비스키)` 입력 여부.

**경로 A (키 없음 — 기본)**: 2026·2027년 대한민국 공휴일 정적 시드
(설/추석 연휴, 대체공휴일 포함 — 실행 시점에 공신력 있는 달력과 대조해 작성) +
관리자 공휴일 편집 UI(추가/삭제, 임시공휴일 대응). 편집은 `logAudit` 기록.

**경로 B (키 있음)**: `GET /api/holidays/sync?year=` 관리자 전용 — 특일정보 API
(`getRestDeInfo`) 호출 → upsert. 편집 UI는 경로 A와 동일하게 제공 (API 누락 보정용).
- **경로 B의 실패 시나리오**:
  - API 응답이 item 1개일 때 XML→JSON에서 배열이 아닌 객체로 옴 (특일정보 API의 악명 높은
    함정). **신호**: 특정 월만 동기화 실패/1건만 저장. **대응 수**: 단일 객체를 배열로 정규화.
  - 키 만료/트래픽 초과. **신호**: `SERVICE_KEY_IS_NOT_REGISTERED` 등 에러 XML.
    **대응 수**: 에러 원문을 응답에 담아 반환, 기존 데이터는 건드리지 않음.
  - **어느 경우든 동기화 실패가 기존 Holiday 행을 지우면 안 된다** — delete-then-insert
    금지, upsert만.

### Move 3 — 휴가 일수 계산에 공휴일 제외

`api/leave/route.ts:93`의 필터에 공휴일 제외 추가:
`getDay !== 0 && !== 6 && !holidaySet.has(ymd(d))`.

- **주의**: 93행 직후 `days === 0` 분기(94행)가 이미 존재 — 전 기간이 주말인 신청 거부.
  공휴일 제외로 이 분기에 걸리는 경우가 늘어난다 (예: 공휴일 하루만 신청). 의도된 동작이므로
  에러 메시지가 공휴일 언급을 포함하도록만 조정.
- **2차 결과**: 반차/반반차(88-90행, 고정 0.5/0.25)는 단일 날짜 — 공휴일에 반차 신청 시
  0.5일 차감되는 문제. **대응 수**: 시작일이 공휴일/주말이면 400 거부 추가.
- **3차 결과**: 이미 승인된 과거 휴가의 days는 재계산하지 않는다 (소급 금지 —
  잔여 연차가 뒤흔들린다). 보고서에 명시만.

### Move 4 — 캘린더/일정 표시

일정 화면(`(dashboard)/schedule`, `work/calendar` 중 사용자가 보는 주 화면)에 공휴일을
읽기 전용으로 표시. `GET /api/holidays?year=` 조회 API 추가.
- **분기 트리거**: 캘린더 컴포넌트가 이미 날짜별 메타데이터 주입 지점을 갖고 있으면 그걸
  사용, 없으면 최소 침습(날짜 셀에 이름 뱃지)으로. 캘린더 리팩터링 금지.

### Move 5 — (정책 대기) 출퇴근 판정 제외

ledger `(공휴일_지각판정_정책)` 기본값(공휴일엔 LATE/EARLY_LEAVE 판정 안 함) 적용 시:
auto-fill의 상태 판정(47-50행)과 clock-in/out의 동일 로직에 공휴일 체크 추가.
**미션 04가 상태 판정을 공용 함수로 추출할 예정** — 04가 먼저 실행됐다면 그 함수 한 곳만
수정, 아니면 각 인라인 위치를 수정하고 04 워게임에 반영 노트를 남길 것.

## 3. 검증

1. 공휴일(예: 2026-10-05 추석 연휴 중 하루)을 낀 5일 연차 신청 → 차감 일수가 공휴일·주말
   제외 값과 일치. DB의 `days` 컬럼으로 확인.
2. 공휴일 하루짜리 연차 신청 → 400 거부.
3. 타임존 검증: 공휴일 당일 경계(자정 직후) 날짜로 판정이 하루 밀리지 않음 —
   `getHolidaySet` 단위 테스트 또는 수동 확인.
4. 회귀 2곳: 공휴일 없는 기간의 연차 신청(기존 일수와 동일해야 함), 잔여 연차 표시.

## 4. 중단 조건 (Abort)

- **C1**: 정적 시드 작성 시 2026~2027 공휴일(특히 대체공휴일)을 공신력 있게 확정할 수
  없으면 — 추측으로 채우지 말고 확실한 날짜만 넣은 뒤 불확실 목록을 ledger에 기록.
- **C2**: 날짜 저장 방식이 정찰과 다르게 뒤섞여 있음(문자열/DateTime 혼재 등) → 타임존
  전제가 무너진 것. 관찰 결과 보고 후 대기.
- **C3**: 경로 B에서 API 스펙이 문서와 다름 (필드명 변경 등) → 파싱을 추측으로 맞추지 말고
  실제 응답 샘플을 보고에 첨부.
